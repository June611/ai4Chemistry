# 失败隔离、batch256与定时同步补查

用户要求：单次实验失败后继续其他实验；后续神经网络训练batch均为256；以最简单的方式
每5分钟采集并同步飞书，无需用户反复唤醒Codex。

## 失败推进

原实现对训练返回非零和产物验收失败均继续后续任务。本次补上子进程启动OSError的隔离：
记录该任务failed、关闭其日志，再继续挑选可运行任务。测试用真实子进程分别模拟训练失败、
启动失败和产物不完整；三种情况下后续独立任务均完成，依赖失败任务的下游均blocked。
全队列最后返回1用于汇报存在失败，不在首个训练失败时立即退出。

Infomax每个seed的预训练是同seed下游的必要依赖；前置失败时不能拿烟测或其他seed权重
代替。其他模型和seed仍可继续。失败任务保留旧产物，重试使用新目录，不自动降batch。

## 训练预算

重新展开默认63项正式计划，并逐份读取生成配置：

- 17个下游神经网络×3seed=51项，加3项QM9 Infomax预训练，共54项，batch均256。
- 所有54项仍为100epoch上限、patience20，训练seed与split seed一致。
- 三个传统模型×3seed=9项，一次拟合，batch/epoch/patience不适用。
- Cormorant/LieTransformer仍由中央暂停清单排除；本次没有启动正式训练。

逐任务审核见[batch_256_followup.csv](verification/batch_256_followup.csv)。

## 定时同步

服务器Python队列每5秒采样资源，保存JSONL/CSV/状态；WSL Python同步桥读取摘要，以
`feishu_sync_seconds: 300`为默认周期更新飞书运行行、硬件快照和完成后的预测附件。
计时扣除同步耗时，网络/API响应较慢时实际时间会延后；失败自动重试，不停止服务器训练。
最终任务结束后，等待全部同步成功才退出。

直接使用已有tmux后台会话运行[操作命令](operations.md)，无需sub2api、LLM agent或新的
调度平台。程序不调用模型API；轮询不会消耗Codex/LLM token。保持电脑不休眠、WSL和网络
可用、CLI授权与SSH连接有效。完整指标使用JSON/CSV原值，缺失字段不推测补齐。

配置冻结、准入、周期设置覆盖，以及最终飞书写入暂时失败后的再次同步。
服务器同样36项通过（2.68s），13份源码/配置/文档部署哈希一致；此前8项诊断仍为completed。
